# Methodology decisions

## Scope

**Audit M1.** "No claim without its sample" (CLAUDE.md rule 2) needs its twin: no claim
without its population. Before any number in this document or in the published leaderboard
is read, the population it was measured against must be stated plainly.

Every item in this project's golden set is **synthetic** -- generated by
`ground_truth/golden/generate.py` (see "Synthetic corpus generator" below), **not real pay applications**.
No item was drawn from, derived from, or fitted to an actual client invoice
or pay application. Every headline number this project publishes -- accuracy, calibration,
judge agreement, cost, latency -- is therefore a statement about performance on this
synthetic corpus only. Its **external validity** to real pay applications -- whether the
same accuracy would hold on real client documents -- is unmeasured, and unmeasured *by
design* at this stage: no real-invoice corpus exists yet for this project to validate
against (see "If Ledger Sense did not produce a partner and a labelled corpus" in the
project brief). Treat every number below as "measured on synthetic data, generalisation to
real invoices unknown," not as a claim about real-world extraction accuracy.

## Definitions

Every term the published leaderboard and this document rely on, defined once, here --
`ground_truth.publish.leaderboard.assert_methodology_defines_every_term` checks this section
against `required_terms()` and fails the build if a term is used without a definition.

- **accurate** -- the deterministic grader registered for that field type returned
  `correct=True` for a given (item, field) pair under the current rubric version. "Accurate"
  is never a judge's opinion where a deterministic grader could have reached the same
  question; it is a specific grader's specific boolean, versioned.
- **correct** -- defined per field type by the rubric, not by judgement. What counts as a
  match (exact string, numeric tolerance, normalised text, an acceptable variant list) is
  fixed in the rubric before labelling and looked up per field type, never decided ad hoc
  while grading one item.
- **field** -- one named, typed slot in an item's schema (e.g. `invoice_total`,
  `retainage_pct`). Grading, rubric versioning, and per-field accuracy intervals
  (`LeaderboardRow.per_field`) are all computed at the field level, not the item level.
- **item** -- one synthetic pay application produced by `ground_truth/golden/generate.py`,
  identified by `item_id` in the public split or by `content_hash` alone once it crosses into
  any published artifact from the private split.
- **replicate** -- one of five independent calls for the same (item, slot) pair. Temperature
  zero is not determinism (CLAUDE.md rule 6): every item x slot combination is run `n>=5`
  times and the mean and variance across replicates are what gets reported, not one run.
- **split** -- one of the two disjoint golden-set partitions, public or private, each
  generated by its own independent seeded call to `generate()` -- never produced by
  generating one pool and dividing it (see "Public/private split" below).
- **public split** -- the split published in full, seeded by `GT_PUBLIC_SEED`, that exists so
  results are independently reproducible. Headline numbers are never computed from the public
  split alone.
- **private split** -- the held-out split, seeded by `GT_PRIVATE_SEED`, that is never
  published. Headline accuracy is computed against it, and only `content_hash` values --
  never `item_id`, raw model output, or expected values -- ever leave this repository for a
  private-split item (`ground_truth/publish/artifacts.py`).
- **verdict** -- one grader's correct/incorrect determination for one (output, field) pair,
  stored with its `grader_id`, `grader_version`, and `rubric_version`. Verdicts are the atomic
  unit every accuracy interval is aggregated from.
- **grader** -- the deterministic or judge component that produces a verdict for a field type:
  exact match, numeric tolerance, normalised match, schema validity, or arithmetic
  consistency: deterministic; an LLM judge is used only where a deterministic grader genuinely
  cannot reach.
- **judge** -- an LLM-as-judge grader. Its verdicts feed headline scoring for a field type only
  where its measured agreement with human labels (Krippendorff's alpha) meets or exceeds the
  pre-registered rejection threshold (`REJECTION_THRESHOLD = 0.667`,
  `ground_truth/graders/judge/agreement.py`); below that threshold the field type is excluded
  from headline scoring and reported as not measured, not silently kept.
- **interval** -- a bootstrap confidence interval carrying five fields together: `point`,
  `low`, `high`, `n`, and `method` (`ground_truth.stats.bootstrap.Interval`). Every accuracy
  figure this project publishes is one of these; there is no code path that emits a bare point
  estimate.
- **list price** -- the provider's published list price for the paid tier, retrieved from a
  dated, cited source URL (`SlotSpec.pricing_url`, `SlotSpec.retrieved_at`). It is never
  measured spend: this benchmark runs on free tiers, where measured cost is zero and would be
  a meaningless -- or fabricated-looking -- number to publish as a cost figure.
- **not distinguishable** -- the stated conclusion when two slots' accuracy `Interval`s
  overlap (`Interval.overlaps`). The sample cannot tell the two models apart at this size, and
  the leaderboard says so in words rather than implying a ranking the data cannot support.
- **minimum detectable effect** -- the smallest true difference a given sample size and
  discordance rate could reliably detect (`ground_truth.stats.mde.describe_mde`). Published
  alongside results so a reader knows what the sample can and cannot see, not only what it did
  see.
- **look** -- one evaluation of the regression watch's accumulated data against its
  pre-registered sequential-testing calendar (up to 13 per quarter). Each look spends part of
  a shared alpha budget under an O'Brien-Fleming boundary (`ground_truth/stats/sequential.py`),
  which is what keeps repeated looks from inflating the false-positive rate the way naive
  repeated significance testing would.
- **rubric** -- the versioned, published document defining what counts as correct per field
  type (exact match, numeric tolerance, normalised match, acceptable variants). Authored and
  published before labelling starts, never reverse-engineered from already-labelled items;
  every verdict cites the `rubric_version` it was graded under.

## Synthetic corpus generator (Task 8)

`../ledger-sense/` was checked before writing `ground_truth/golden/generate.py`. As of
2026-08-30 its worktree (`phase-0-platform`) contains only auth/storage/API-stub code --
the extraction and generation phases have not started there, and a search for
pay-application/G702/G703/AIA/invoice generator code found only incidental comment
matches, no generator to wrap. The synthetic corpus generator is therefore implemented
locally in `ground_truth/golden/generate.py`, per this project's own design, rather than
wrapping a sibling-project component. No AIA form artifact is reproduced; the rendered
documents use this project's own layout and wording with equivalent column semantics
only.

## Public/private split and the hash salt (Task 9)

The public and private corpora are generated by two independent calls to `generate()`
under two disjoint seeds (`GT_PUBLIC_SEED`, `GT_PRIVATE_SEED`), never by generating one
pool and splitting it (audit B4a). `build.py` refuses to run if `GT_PUBLIC_SEED`,
`GT_PRIVATE_SEED`, or `GT_HASH_SALT` is under 32 characters (128 bits, matching
`secrets.token_hex(16)`'s output length) -- naming which variable failed the check and
why.

The split's security does **not** rest on any seed being withheld: this repository is
public from its first commit, so `generate.py` has never been secret and never will be.
`GT_PUBLIC_SEED` is likewise not secret -- the public split it drives is published in
full anyway, so there is nothing left for its value to protect (see below for the actual
value used, published for reproducibility). What must stay secret is `GT_PRIVATE_SEED`
and the salt folded into every `content_hash`
(`sha256(f"{salt}:{seed}:{n}:{payload}")`, audit B4): without the salt, `content_hash`
would be fully enumerable from the seed alone once `generate.py` is public, so the
published `manifest_private.json` hashes would carry no more commitment strength than
the seed's own entropy. With a private, high-entropy salt, the hashes prove the private
items existed at a given date (`git log` on `manifest_private.json`) without an outside
party being able to reconstruct or verify individual items against them -- only whoever
holds `GT_PRIVATE_SEED` and `GT_HASH_SALT` can regenerate the private corpus and confirm
a hash matches. Both are generated with `secrets.token_hex(16)`, kept only in the
gitignored `.env`, and backed up outside the repository -- losing either means the
private split can never be regenerated, rotated, or re-proven to exist.

### Reproducing the shipped public corpus

`build.py` enforces the same >=32-character entropy floor on `GT_PUBLIC_SEED` as on the
private seed and salt (the brief's Step 5 and the task-9 audit note both state the check
applies to all three variables, not just the two the private commitment depends on). The
illustrative `GT_PUBLIC_SEED=42` in `.env.example` is a placeholder for readability, not
the value the shipped `golden/corpus/public/` and `golden/manifest_public.json` were
built from -- `42` is 2 characters and `build.py` refuses it. Because `GT_PUBLIC_SEED` is
not secret, the real value used for the shipped build is published here rather than only
in the gitignored `.env`, so the public corpus stays independently reproducible:

```
GT_PUBLIC_SEED=32611816645452341011091101610726
```

`GT_PRIVATE_SEED` and `GT_HASH_SALT` are never published anywhere, by design -- see
above.

## Phase 2 — Measurement

> **NOT A MEASUREMENT RUN.** This section documents Phase 2's *code and its own internal
> validation* -- the judge, statistics, matrix, and calibration modules, and the null
> simulations that check them against known distributions. **It is not a report of a
> completed real-data sweep.** No sweep has been executed against live providers in this
> session: `data/results.duckdb` does not exist, `tests/test_phase2_e2e.py`'s 8 tests all
> `SKIP` with "run the sweep first: python -m ground_truth.schedule", and every number below
> that is not explicitly labelled as simulation output is **pending**, not measured. Do not
> quote anything in this section as a result of running the harness against real models.

### What is real: the statistics, verified by simulation

The two figures below come from pure Monte Carlo simulation of the sequential-testing code
itself (`tests/stats/test_sequential.py`, seed fixed, 20,000-trial null). They do not depend
on any provider call, sweep, or golden item -- they are a property of the math, verified
against the code that implements it.

- **Naive fixed-threshold type-I error: `0.2119`.** A regression watch that simply compares
  `|z| > 1.96` at every one of 13 correlated weekly looks -- the naive approach this project
  rejected -- falsely flags a null (no real regression) trajectory **21.19% of the time**
  against a nominal 5%, measured over 20,000 simulated 13-look quarters
  (`test_fixed_threshold_inflates_alpha`). This is the measured reason the regression watch
  uses O'Brien-Fleming alpha spending instead of a fixed per-look threshold: naive repeated
  significance testing at 13 looks a quarter would report a "regression" about 1 look in 5
  purely from noise.
- **Calibrated O'Brien-Fleming boundary constant: `C_OBF_13_LOOKS = 2.1023`.** For this
  project's pre-registered 13-look-per-quarter calendar, `C = 2.1023` is the constant
  (`ground_truth/stats/sequential.py`) that keeps the *cumulative* type-I error across all 13
  correlated looks at the nominal 0.05 (`test_calibrated_constant_controls_alpha`, verified
  over the same 20,000-trial null simulation, rate constrained to `[0.043, 0.057]`). It
  replaces the naive `z_{alpha/2} = 1.96` boundary, whose own miscalibration is documented
  separately in `docs/analysis-plan.md` (substituting 1.96 for `C` inflates the *O'Brien-Fleming
  shaped* boundary's true error to 0.0721 -- a different, smaller failure mode than the fully
  naive fixed-threshold test above, which has no spending function at all).

### What is pending: requires the real sweep

None of the following exist yet. Each requires `python -m ground_truth.schedule` to run
against real providers and populate `data/results.duckdb`; no number is invented here in its
place.

- [ ] **Run schedule and observed wall-clock** -- when the sweep ran, how it was batched
  across providers' free-tier rate limits, and how long it actually took.
- [ ] **Slot survival** -- how many of the configured model slots completed the sweep, and
  why any were dropped (rate limit exhaustion, provider error, deprecation).
- [ ] **Judge configuration and family separation** -- which model slot(s) served as judge,
  and the record showing the judge's family differs from every model slot it scored
  (`test_same_family_judge_rejected` exercised against real `models.yaml` entries, not a
  fixture).
- [ ] **Judge-agreement table** -- Krippendorff's alpha per field type the judge touched, its
  confidence interval, and accept/reject status against `REJECTION_THRESHOLD = 0.667`
  (`docs/analysis-plan.md`, "Judge rejection threshold"). Every field type the judge scored
  must appear, including rejected ones.
- [ ] **Order-effect and length-effect figures** -- the measured test for a presentation-order
  effect and for a length-cue effect in the judge's verdicts, run against real judge samples.
- [ ] **Calibration public/private divergence** -- the observed gap between the reliability
  curve fitted on the public split and its validation against the held-out private split.
- [ ] **Human labels, round 1** -- collected, with the collection date recorded here. Phase
  3's round-2 blind re-labelling needs a minimum two-week gap measured from this date, so the
  date is load-bearing, not decorative.

Until every item above is checked off with a real figure and a real date, the Phase 2 exit
criteria (see the plan's task list) are not met, and no "Phase 2 complete" tag should exist
on this branch.
