# Methodology decisions

## Synthetic corpus generator (Task 8)

`../ledger-sense/` was checked before writing `ground_truth/golden/generate.py`. As of
2026-08-30 its worktree (`phase-0-platform`) contains only auth/storage/API-stub code --
the extraction and generation phases have not started there, and a search for
pay-application/G702/G703/AIA/invoice generator code found only incidental comment
matches, no generator to wrap. The synthetic corpus generator is therefore implemented
locally in `ground_truth/golden/generate.py`, per this project's own design, rather than
wrapping a sibling-project component. No AIA form artifact is reproduced; the rendered
documents use this project's own layout and wording with equivalent column semantics
only.

## Public/private split and the hash salt (Task 9)

The public and private corpora are generated by two independent calls to `generate()`
under two disjoint seeds (`GT_PUBLIC_SEED`, `GT_PRIVATE_SEED`), never by generating one
pool and splitting it (audit B4a). `build.py` refuses to run if `GT_PUBLIC_SEED`,
`GT_PRIVATE_SEED`, or `GT_HASH_SALT` is under 32 characters (128 bits, matching
`secrets.token_hex(16)`'s output length) -- naming which variable failed the check and
why.

The split's security does **not** rest on any seed being withheld: this repository is
public from its first commit, so `generate.py` has never been secret and never will be.
`GT_PUBLIC_SEED` is likewise not secret -- the public split it drives is published in
full anyway, so there is nothing left for its value to protect (see below for the actual
value used, published for reproducibility). What must stay secret is `GT_PRIVATE_SEED`
and the salt folded into every `content_hash`
(`sha256(f"{salt}:{seed}:{n}:{payload}")`, audit B4): without the salt, `content_hash`
would be fully enumerable from the seed alone once `generate.py` is public, so the
published `manifest_private.json` hashes would carry no more commitment strength than
the seed's own entropy. With a private, high-entropy salt, the hashes prove the private
items existed at a given date (`git log` on `manifest_private.json`) without an outside
party being able to reconstruct or verify individual items against them -- only whoever
holds `GT_PRIVATE_SEED` and `GT_HASH_SALT` can regenerate the private corpus and confirm
a hash matches. Both are generated with `secrets.token_hex(16)`, kept only in the
gitignored `.env`, and backed up outside the repository -- losing either means the
private split can never be regenerated, rotated, or re-proven to exist.

### Reproducing the shipped public corpus

`build.py` enforces the same >=32-character entropy floor on `GT_PUBLIC_SEED` as on the
private seed and salt (the brief's Step 5 and the task-9 audit note both state the check
applies to all three variables, not just the two the private commitment depends on). The
illustrative `GT_PUBLIC_SEED=42` in `.env.example` is a placeholder for readability, not
the value the shipped `golden/corpus/public/` and `golden/manifest_public.json` were
built from -- `42` is 2 characters and `build.py` refuses it. Because `GT_PUBLIC_SEED` is
not secret, the real value used for the shipped build is published here rather than only
in the gitignored `.env`, so the public corpus stays independently reproducible:

```
GT_PUBLIC_SEED=32611816645452341011091101610726
```

`GT_PRIVATE_SEED` and `GT_HASH_SALT` are never published anywhere, by design -- see
above.
